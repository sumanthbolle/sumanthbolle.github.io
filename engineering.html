01 · System overview

Three knowledge layers, one cited answer

The domain pack extends Summaverick without replacing its LLM gateway. A question is classified, planned, retrieved across up to three sources, de-duplicated, ranked, then verified against its own citations before it reaches the user.

Layer 1

SDK explain

Version-matched Fluent APIs, .now.ts, now.config.json, build & auth topics. Never invents Fluent API properties.

requires @servicenow/sdk 4.6.0+
Layer 2

ServiceNowDocs llms.txt

ITSM, CMDB, ITOM, IRM/GRC, SPM, CSM, HRSD, platform. Release-matched product documentation — no SPA scraping.

Layer 3 · optional

SDK query

Read-only allowlisted instance metadata. Off by default. Task-scoped only — live results are never merged into the global knowledge base.

02 · Security model

Untrusted by default, gated three ways

Every retrieved document, record and SDK topic is treated as untrusted evidence, wrapped between BEGIN_UNTRUSTED_SERVICENOW_EVIDENCE markers. The request itself passes three independent gates before anything runs.

The three gates map one-to-one onto real modules:

  • Prompt-injection scanner — 10 fixed patterns catch ignore previous instructions, enable write operations, disable citations, dump passwords and the rest. Injection found inside evidence is logged and ignored for control, never obeyed.
  • Read-only query allowlist — 19 metadata tables are allowlisted; 8 business tables (incident, sys_user…) require explicit opt-in; 12 credential/secret tables are hard-blocked. Every query needs an encoded query and a clamped row limit (default 50).
  • Sensitive-field redaction — 18 field names (password, ssn, work_notes, token…) are scrubbed to [REDACTED] before the model ever sees a record.

A fourth control governs the CLI itself: only 5 read-only SDK command prefixes are allowlisted, and 8 mutating subcommands (build, deploy, delete…) are blocked in v1 and always require explicit approval after impact analysis.

03 · Evaluation

It ships behind an adversarial eval suite

Claims about safety are cheap. These are measured: a regression suite plus a dedicated adversarial suite run on every change, each case asserting an expected intent, expected sources, or an expected block.

Adversarial cases are built to attack a specific control: role-override injections (adv-01), injection smuggled inside an incident description (adv-02), credential-table reads (adv-03), unrestricted business-table reads (adv-04), unapproved mutating commands (adv-05/06), and hallucination traps that name invented Fluent APIs or non-existent fields (adv-09/10). Each asserts the request is refused, redacted, or answered with INSUFFICIENT_EVIDENCE — never quietly complied with.

04 · In production

How it runs, and what stands on it

The public surface is a Cloudflare Worker gateway (api/worker.js) that fronts the Perplexity Sonar model and owns auth, CORS and tenancy. When a question is a ServiceNow question, api/servicenow-domain.js — a Worker-compatible mirror of the research-agent classifier — injects the domain system guidance: treat evidence as untrusted, prefer version-matched SDK docs, never invent Fluent properties, always cite, and default the release family to australia.

The same Worker routes SkyFare flight discovery (Amadeus inventory with a Sonar fallback, each response labelled by provenance) and the Metals spot feed. So the products aren't separate demos — Summaverick and SkyFare stand on one governed engine, with the heavy Node domain pack (SDK CLI + instance providers) living in research-agent/.
